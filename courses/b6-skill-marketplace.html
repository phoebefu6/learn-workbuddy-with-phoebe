Part 1 · covers skill packages + composable workflows from the official guides

A skill is a saved HOW 6 min live

WorkBuddy ships 20+ reusable skill packages - research, analytics and more - and lets them compose into repeatable workflows. Strip the branding and a skill is exactly one thing: an instruction that earned its levers, saved with the volatile parts turned into parameters. Goal, format, Expert and verify ask freeze; the file path becomes a blank you fill at run time. The distinction to keep straight all night: an Expert is WHO does the job (b5's clause); a skill is the HOW you refined once and never want to re-type.

LiveWhat deserves to become a skill4 min▶

Not every instruction earns freezing. Three tests, all must pass:

  • It recurs - weekly briefing, monthly variance readout, every-deal competitor scan. One-off tasks stay one-off instructions.
  • It is proven - you have run it by hand at least twice and the deliverable landed both times. Freezing a lever that is still loose just repeats the failure on schedule.
  • Only the inputs vary - if the goal or format changes run to run, it is two tasks wearing one name. Split them, then freeze each.

The built-in packages follow the same logic at Tencent's scale: research and analytics workflows someone proved, parameterized, and shipped 20+ of. Browse them before building your own - the chore you hate may already be packaged.

Part 2 · covers the Skill Marketplace + its automatic security scanning

The marketplace, and the checkpoint that stays yours 6 min live

The Skill Marketplace is where skills stop being personal: browse what others built, install what fits, compose installed skills into workflows. Tencent runs automatic security scanning on marketplace skills - real, documented, and worth having. But treat it the way you treat a browser-extension store's scan: necessary, not sufficient. Before installing anything, you read what it can touch. That checkpoint does not automate.

Skills inherit your folder authorization An installed skill cannot reach anything you have not already granted - it operates inside the same boundary you drew in b1. That is exactly why the one-project rule keeps paying: with only ~/Documents/Meridian authorized, the worst a bad skill can do is rearrange one folder, and the audit trail shows every touch. Widen access for a skill the way you widen it for anything else: deliberately, folder by folder, never to make an install prompt go away.

Your b2 template becomes a custom skill ★ 14 min · everyone does it

The official docs walk this exact path as the Custom Skills practice case - and your raw material is already written: the five-lever briefing instruction you saved in b2 and have run by hand since. Tonight it stops being a note you paste and becomes a skill you invoke.

Open your b2 template and audit the levers once more. Goal + audience, files by name, exact format, Expert if any, verify ask. Anything still loose gets fixed now - a skill repeats whatever you freeze, good or bad.

Create the custom skill following the Custom Skills practice case in the docs. Paste the template as the skill's instruction body.

Parameterize the file paths. Replace the hard-coded sg-sales-2026.xlsx with an input parameter. Everything else - the one-pager format, the 15-word bullets, the verify ask - stays frozen. The blank is the only thing next week should have to fill.

Save, then re-run the skill on a different file in your Meridian folder. Read the plan at the gate exactly as you would for a typed instruction - skills do not skip the confirmation gate, and tonight you verify that with your own eyes.

Compare the skill run against your last manual run. Same structure, same discipline, zero typing. That delta, multiplied by every week this chore recurs, is what this session is worth.

Build-along 2 of 2

Compose a two-step workflow ★ 12 min · everyone does it

Skills compose: the output of one becomes the input of the next. You will chain a research skill into a report skill on Meridian and watch the handoff - the moment a file produced by step one turns up as named context in step two's plan.

Pick the two skills. A research skill (built-in package or the marketplace's - vet it first) and a report skill. Task: fresh scan of Meridian's three MY competitors - Highland Leaf, TehMas, Cameron & Co - flowing into a one-page update memo.

Wire the handoff: the research skill writes its findings file into ~/Documents/Meridian; the report skill's input parameter points at that file. One folder, both steps inside the b1 boundary.

Run it and watch the seam. At step two's plan gate, confirm the input is the file step one just produced - not a stale copy, not a guess. The handoff is where composed workflows quietly go wrong; the plan gate is where you catch it.

Read the final memo against the b4 competitor matrix. Anything new since b4 is genuine signal; anything contradictory goes on your verify list. Composition multiplies output - it does not multiply trust.

Why this pattern matters beyond tonight. Research-then-report is the smallest composed workflow that earns its keep - and it is the seed of b8, where the same pipeline runs on a schedule and lands in Slack every Monday without you. Tonight you compose it; b8 makes it fire itself.

Homework

Try it yourself - this week ◐ 25-35 min total

  • Build one custom skill for your own recurring chore - the task you identified in b1, refined in b2, and have now run by hand enough times to trust. Apply the three tests: recurs, proven, only inputs vary. Parameterize, save, run once for real.
  • Uninstall one skill you do not use. Every installed skill is standing capability inside your boundary; unused capability is pure risk with zero payoff. Pruning is part of the discipline, not an afterthought.
  • Browse the marketplace for ten minutes with the vet checklist in hand: what does each interesting skill declare it can touch, and who published it? Install at most one - after reading, not before.
  • Re-run your composed workflow once mid-week and note where the handoff file lands. If you cannot find it in seconds, name the output path explicitly in the skill - future-you (and b8's scheduler) will thank you.

Check yourself

Three questions before you go 🎯 ◐ 90 seconds

1 · Skills vs Experts - which statement is right?

b5's clause hires the specialist; tonight's skill freezes the way you asked. They compose: your custom briefing skill can name an Expert inside it, and usually should.

2 · The marketplace scans skills automatically. Why do you still read what a skill can touch before installing?

Browser-extension discipline: the store scan filters known-bad, but only you know whether "reads all authorized folders + posts to chat platforms" is fine for the folder you granted. The vet checkpoint does not automate.

3 · What can an installed skill reach on your machine?

The b1 boundary binds every skill, built-in or installed. A publisher can declare wants; your authorization decides gets. With one folder granted, the worst case stays one folder - and the audit trail records every touch.
