Part 0

Why this is the hardest session

Not because the clicks are hard - linking a platform takes two minutes. It is the hardest because both features remove friction that was quietly protecting you. Remote control removes the desk; Memory removes the retyping. Friction removed is judgment exposed: the plan you used to read on a big screen now arrives on your phone between meetings, and the defaults you used to type consciously now apply themselves. Tonight is about taking both powers and keeping the operator's two checkpoints - approve the plan in, verify the deliverable out - intact at a distance.

Part 1 · covers the official Install & Use guide (remote control), Platform Integration docs

Your phone drives, your desktop does 6 min live

In the Assistant settings you link Slack, Telegram or Discord (the docs also list WeChat Work, Feishu, DingTalk and QQ - pick whichever chat app already lives on your phone). From then on, a message in that chat is a task instruction: your desktop at home wakes up, plans, executes in its sandbox on its authorized folders, and posts the deliverable back into the same thread. Nothing runs ON the phone. The desktop executes; the chat is the leash.

LiveWhat remote is actually for3 min▶

Remote is not a gimmick; it changes when work can start. The patterns that pay:

  • Commute-start - trigger the data merge on the train so the deliverable is waiting when you sit down.
  • Meeting-reactive - leadership asks a question at 2pm; you fire the analysis from the hallway and paste the answer before the meeting ends.
  • Checking on b8 - your scheduled briefing ran at 7am; from the kitchen you ask for status and read the result without opening a laptop.

Notice what all three share: the task family was already proven at the desk (b3, b4, b8). Remote is for tasks you already trust the shape of - it is a distance extension, not a place to try new task types for the first time.

Self-studyWhich platform should you link?2 min read▶
  • Already on Slack all day? Link Slack - the deliverable lands where your team already looks, and b8's briefing push shares the wiring.
  • Want work and life separated? Telegram or Discord keeps WorkBuddy out of your employer's workspace and its retention policies.
  • One platform is plenty. Every linked platform is another surface that can issue instructions to your machine - link the one you will use, not all of them. Re-verify the current platform list at workbuddy.ai; it drifts.
Part 2 · covers Task Management docs + the plan-confirmation behavior from b1

The plan gate on a small screen 6 min live

From chat you can create a task, check its status, and view results - the same task management you know, at a distance. What changes is not the mechanics; it is you. The plan still arrives for confirmation, but now you read it on a phone, walking, between two other notifications. A plan skimmed in four seconds and approved with a thumb is not a plan gate - it is a rubber stamp with extra steps. Remote work needs sharper instructions precisely because the plan check gets weaker.

LiveCreate, check, view - the remote verbs3 min▶

Three things you can do from the chat thread, and the operator's rule for each:

  • Create a task - send the instruction as a message. Rule: write it like a b2 template, not like a text to a friend. "Run the Meridian weekly briefing from ~/Documents/Meridian, one page, bullets max 15 words, cross-check figures, attach audit trail" - yes, all of it, from your thumbs. Saved templates make this a paste, not an essay.
  • Check status - ask what is running and where it is. Rule: status checks are free; use them instead of anxiety.
  • View results - the deliverable and its summary post back to the thread. Rule: the verify checkpoint still applies. Reading a result on your phone does not make it verified; it makes it read.
Remote + scheduled together = the least-supervised mode WorkBuddy has b8 removed you from the trigger; tonight removes you from the desk. Combine them and work runs with no human at either end - which is the goal, and the risk. The non-negotiable: keep a verify ask in every remote instruction and every scheduled template, so the audit trail is always attached when you finally do look. Unsupervised execution is fine; unsupervised SHIPPING is not.
Part 3 · covers the Memory docs (private, editable defaults)

Memory: the format lever, made permanent 6 min live

Memory is private to you and editable - a small panel of standing defaults: who you are, what you work on, how you like output shaped. In b2 you learned that Memory can hold the Format lever for you. Tonight it does, permanently: write "my briefings are always one page, bullets max 15 words" once, and every future instruction inherits it without you typing it. Your instruction and your Memory defaults merge into the effective instruction the agent actually plans from.

LiveWhat belongs in Memory - and what does not3 min▶

Belongs: your role and project ("marketing analyst, working on Meridian's Malaysia entry"), standing format rules ("briefings one page, bullets max 15 words", "currency figures always show the source currency"), tone defaults ("plain English, no jargon"). Things true of EVERY task.

Does not belong: anything per-task (goals, file names, deadlines - those are instruction work), anything you would not want silently applied in three months, and anything secret. Memory is private to you, but it is still a standing input to every plan - treat it like a config file, not a diary.

The test for a candidate default: "would I be happy discovering this clause was silently added to a task I run in November?" If you hesitate, it goes in the instruction, not in Memory.

Self-studyWhy the monthly audit is not optional2 min read▶

Memory fails the way b2's verify lever taught you things fail: silently. A default you set in August ("everything relates to the Malaysia launch") is quietly wrong by November when the launch has shipped - and every deliverable tilts toward a project that no longer exists, with no error message anywhere. So the audit is calendared, not remembered: once a month, open Memory, read every line, ask "still true?", delete or update what is not. Two minutes. It is the same discipline as b8's scheduled-task review - anything that acts without you must be re-checked by you on a schedule.

Build-along 1 of 2

Link, trigger, and feel the rubber-stamp pull ★ 12 min · everyone does it

You will run the Meridian briefing from your phone - and on the way, deliberately experience the exact failure mode Part 2 warned about, in a task where it cannot hurt you.

Link a platform. Desktop app → Assistant settings → link Slack, Telegram or Discord. Follow the connect flow for your platform; send a hello message both ways to confirm the wire is live.

Trigger from your phone. Put the laptop lid HALF closed (machine on, your hands off). From the chat app, send the briefing instruction: "Build the Meridian weekly briefing from ~/Documents/Meridian - one page, bullets max 15 words, cross-check every figure, attach the audit trail."

When the plan arrives in chat, do NOT approve for 10 full seconds. Count them. Feel your thumb hovering. That pull toward instant approval - notification in, tap, done - is the rubber-stamp reflex, and now you have met it in a safe task instead of discovering it in a dangerous one.

Now actually read the plan - right files? right output? - then approve. Watch status if you like, or pocket the phone: the desktop is executing either way.

Read the deliverable in the thread. Same file quality as a desk-triggered run - the loop, the sandbox and the audit trail never moved. Only your keyboard did.

Real world

The 10-second rule scales. Operators who keep a beat of deliberate delay on phone approvals catch the mis-scoped plan a few times a year - the one where "clean up the folder" was about to mean something else entirely. Ten seconds against a shipped mistake is the cheapest insurance in this course.

Build-along 2 of 2

Write your Memory, watch it land ★ 10 min · everyone does it

b1 told you to leave Memory empty. Tonight you fill it deliberately - three lines, no more - and prove to yourself that the defaults actually reach the plan.

Open Memory in settings. Write your role line: who you are and what project you are on, one sentence. Example: "I am a marketing analyst working on Meridian, a Singapore tea brand entering Malaysia."

Add two format rules you are tired of retyping. The classics: "My briefings are always one page, bullets max 15 words" and "Always show currency codes next to figures." Yours may differ - steal from the format clauses you keep writing in b3-b8.

Rerun a task WITHOUT the format clause. Send "Summarize this week's Meridian sales from ~/Documents/Meridian" - note that you did not say one page, did not say bullets.

Spot the defaults landing. Read the plan: the one-page shape and the bullet rule are there anyway. Your Memory just held the Format lever for you. That is the whole feature.

Calendar the audit. Recurring event, first weekday of each month, two minutes: "Open WorkBuddy Memory, read every line, delete what is stale." Do it now, phones are already out.

Homework

Try it yourself - this week ◐ 20-30 min total

  • One remote-triggered task per day this week, real work, from wherever you are - commute, kitchen, hallway. Every plan gets the 10-second read before approval. By Friday the discipline should feel like a habit, not a rule.
  • After three remote runs, review your instructions: which lever did you skimp on when typing with thumbs? Tighten your saved template so the phone version is as sharp as the desk version.
  • Confirm the Memory audit is on your calendar for next month. When it fires, actually do it: read every line, ask "still true?", fix what is not.
  • Preview for b10: open the audit trail of one remote task and read it end to end. Next session turns that skim into the shipping discipline for the whole Meridian pack.

Check yourself

Three questions before you go 🎯 ◐ 90 seconds

1 · When you trigger a task from your phone via Telegram, where does the work execute?

The desktop executes; the chat is the leash. Every boundary you set in b1 - folder authorization, sandbox, audit trail - stays exactly where it was. Only the keyboard moved, which is also why the desktop must be on and signed in.

2 · Why do remote instructions need to be SHARPER than desk instructions?

The mechanics are identical; the human is not. Reading plans on a phone is where rubber-stamping starts, so the fix moves upstream: five levers in every remote instruction, and the 10-second read before every thumb-approval.

3 · Which of these belongs in Memory?

Memory holds what is true of EVERY task - your role and standing format rules. File names and deadlines are per-task instruction work; put them in Memory and they become stale defaults silently steering future tasks. Set deliberately, audit monthly.
