Part 1 · covers Tencent Cloud "What WorkBuddy Can Do", launch announcements

You say, it does 7 min live

Tencent's own framing is the whole product in four words: "you say, it does." A chatbot gives you advice about your work; WorkBuddy gives you the work - a report, a deck, a merged spreadsheet, a renamed folder. Under the hood it is a multi-agent system: your instruction gets decomposed into sub-tasks routed to specialist agents that run concurrently. You never manage that machinery. You manage the instruction and the result.

LiveWhat it can actually do (and where it shines)4 min▶

The documented task families, straight from Tencent Cloud's capability guide - keep this list, it is your delegation menu:

  • Documents + reports - work reports, technical docs, meeting notes from a brief description; descriptions turned into finished slide decks.
  • Data analysis - reads your CSV and Excel files, finds trends, builds charts and dashboards.
  • Research - compiles multi-source research into organized reports and competitive matrices.
  • File operations - batch renaming, organizing, format conversion across whole folders.
  • Scheduled automation - hourly, daily, weekly or one-time runs, pushing results to Slack, Telegram, Discord, WeChat Work, Feishu, DingTalk or QQ (b8).

Behind these sit 100+ built-in Experts (b5), 20+ skill packages (b6), and connectors to GitHub, Jira, Confluence, Google Drive, Gmail, Notion and Slack (b7). It can also switch between models - Hunyuan, DeepSeek, GLM, Kimi, MiniMax - though the default is fine for standard office work.

Self-studyWhat it is NOT - honest edges3 min read▶

Independent reviews and Tencent's own docs agree on the edges. Knowing them makes you faster, not slower:

  • Output still needs your verification before it leaves the building - b10 makes this a discipline, and b2's simulator shows you exactly why.
  • The global edition is young (worldwide launch May 2026) - international support and some features lag the China edition; UI names drift between updates.
  • Advanced setups have real complexity - connectors and custom skills (b6-b7) take patience the first time.
  • It executes; it does not decide for you. What is worth doing, for whom, to what standard - that stays your job. The whole leader track is about exactly this.

The permission boundary 6 min live

An agent that can touch your files is only as safe as the boundary you draw on day one. WorkBuddy's boundary has three layers: folder authorization (it can only see folders you granted), plan confirmation (you approve the steps before anything runs), and sandboxed execution (tasks run contained, with an audit trail of every change). The operator's discipline is to keep all three tight - starting with one project folder, not your whole disk.

LiveFolder strategy: the one-project rule3 min▶

Tonight you create ~/Documents/Meridian and authorize only that. Everything the course touches lives there. The payoffs:

  • Blast radius - a misunderstood instruction can only rearrange one folder, not your life.
  • Better results - a scoped folder means the agent finds the right files instead of guessing among thousands (this becomes the Context lever in b2).
  • Clean audits - one folder, one project, one reviewable trail of changes.

Widen access later, deliberately, folder by folder - after b2 has taught you what the agent does with what it can see. Never grant the whole home directory to get past a permission prompt.

Self-studyPermission Modes + Data Management, in plain words3 min read▶

Two settings pages worth opening once this week:

  • Permission Modes - how much the agent may do between confirmations. Start conservative: confirm plans, confirm outward actions. Loosen per-task-type only once a pattern has earned trust (b8's scheduled tasks are where this matters).
  • Data Management - what is stored, where, and how to clear it. The desktop app works on local files without a mandatory cloud upload - one of WorkBuddy's genuine differentiators - but connectors (b7) change that picture per-connector, so revisit this page then.
  • Memory - private to you, editable defaults (your role, preferred formats). Leave it empty tonight; b9 fills it deliberately.

Install + scope the boundary ★ 10 min · everyone does it

Straight from the official overseas guide. Requirements: Windows 10/11 or macOS 10.15+, about 150-180 MB, stable internet. Free plan is fine for the whole course.

Download from workbuddy.ai - WorkBuddySetup.exe on Windows, WorkBuddy.dmg on macOS (drag to Applications; if blocked: System Settings → Privacy & Security → Open Anyway).

Sign in with your account. Default model settings are fine for standard office work - do not touch Model Configuration tonight.

Create the project folder: ~/Documents/Meridian. Drop in any two or three spreadsheets or docs you have lying around - real material, not toys.

Authorize ONLY that folder when the folder-access prompt appears. Decline the broad grants. This is Layer 1, set correctly on day one.

Teams plan note (for the leader track cohort) Team seats run ~$40/seat/month with 1,000 pooled Credits and an Admin Console for centralized governance - a5 covers the economics. Operators: the free tier carries this whole course; re-verify plans at workbuddy.ai, they drift.

Your first finished deliverable ★ 12 min · everyone does it

The official guide's advice for a first instruction: describe the task in plain language - the more specific, the better. You will feel the four-stage loop once, end to end, on your own files.

Instruct. In the task bar, describe one real chore on the files in your Meridian folder. Pattern to imitate: "Merge every Excel file in ~/Documents/Meridian into one sheet, then generate a bar chart plus a one-page summary of what stands out."

Read the plan. WorkBuddy shows its steps before running - Understand and Plan made visible. Check: right files? right output? Then confirm. Never rubber-stamp; this gate is your seatbelt for the rest of the course.

Watch it act. Sub-tasks execute in the sandbox. Notice you can keep working - this is delegation, not supervision.

Open the deliverable. A real file, plus the audit trail of what changed. Skim the trail once tonight so you know where it lives - b10 turns that skim into a discipline.

Say the contract out loud: one instruction in, one verifiable file out. Everything else in this course is about making both sides of that contract sharper.

Real world

Why the plan gate matters. "Clean up the Q1 folder" can mean archive-by-month or delete-the-duplicates. Same words, opposite file operations. The plan screen is where that ambiguity surfaces BEFORE anything moves - and b2's simulator is an hour of learning to kill the ambiguity in the instruction itself.

Check yourself

Three questions before you go 🎯 ◐ 90 seconds

1 · What makes WorkBuddy different from a chatbot?

"You say, it does." A chatbot tells you how to merge the files; WorkBuddy hands you merged-q1.xlsx plus an audit trail. Model size is not the difference - execution is.

2 · The safest folder-access setup for your first week is:

One folder = small blast radius, better file-finding, clean audit trail. Broad grants trade a moment's convenience for a permanent loss of the boundary. (And pasting everything defeats the point of an agent with file access.)

3 · Where does YOUR judgment sit inside the four-stage loop?

Two checkpoints, not zero and not constant babysitting: approve the plan going in, verify the deliverable coming out. That is the operator's whole rhythm - b2 sharpens the input, b10 sharpens the output check.
